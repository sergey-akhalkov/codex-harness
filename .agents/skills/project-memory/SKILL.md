# Project memory

Establish the actual Git checkout root, including linked worktrees. Follow its instruction route to the short memory index at the start of substantive work and after a context reset. Read only entries relevant to the task; an index link is not a request to load every body.

When adopting memory, discover existing decision, context and verification records first. Reuse the declared entry point. If none exists, adapt [the index template](assets/index.md) as `docs/memory/README.md` and add a short relative route in the project's `AGENTS.md`. Existing records remain authoritative; the index links to them without copying their contents. Create a topic file with [the entry template](assets/entry.md) only for useful knowledge that has no existing home.

Distinguish confirmed user decisions, verified observations, tentative ideas and superseded statements. Keep scope, evidence and a date or relevant source identity sufficient to reassess each entry. Current instructions and fresh source evidence take precedence over memory. When a user changes a decision, update its owning record and reconcile affected references, preserving useful reasons for supersession.

Before relying on a technical entry, compare its relevant source, configuration, runtime and dirty inputs with current conditions. Recheck a changed command through the project's native verification path; when available use `project-verification` and its command-record format. Keep historical success separate from current applicability, and mark uncertainty explicitly until checked.

Record durable decisions during discussion and reusable technical findings once verified. Reread current content before a narrow edit in the owning checkout; preserve unrelated changes. No useful new knowledge means no write. Do not add progress logs, duplicate facts, credentials, session transcripts, native Codex memory databases or runtime state to Git. Memory maintenance needs no separate model call.

Updates are reviewable working-tree edits, with no implied commit, push or propagation to another worktree. If integration conflicts, retain both versions and their evidence, then reconcile using current user decisions and verified facts. Disconnecting a global skill must leave the project's text records intact.

# Sequential improvement records

Beads remains the sole owner of task, hypothesis and decision status. Native
`codex-harness feedback hypothesis-*` commands retain investigation, trial and
implementation references on the existing cards. Read the installed command
help for request fields; do not maintain another hypothesis journal. A
controller cursor records recovery position and references these owners.

Search open, closed and deferred hypotheses before admission. A repeated trial
uses the same hypothesis card. Reconsider an earlier rejection only with a new
basis linked to the earlier conclusion. Candidate A and workload B have a
nonblocking relationship: finishing A's investigation does not require a
benefit verdict for B. This hypothesis path does not manufacture incubator
votes or change the ordinary feedback-promotion policy.

Each hypothesis and workload references its own complete OpenSpec change and
independent acceptance. Retain attributable observations separately from
inferences and predictions. The trial references exact source, specification,
runtime and policy identities, both arms, acceptance results, metric coverage
and useful artifacts. Private evidence stays in the owning local project;
public board output contains no private deployment details or raw traces.

Use the existing benefit-gate publication for adopt, reject or inconclusive
results. A recorded decision is not proof that acceptance ran. Missing,
contradictory or expired evidence cannot authorize adoption. Publish retries
idempotently without erasing failed attempts. Keep integration, experimental
activation and live publication references distinct from the benefit result.

Removal proposals and explicit user decisions use the same card via
`feedback removal-propose`, `removal-decide` and `removal-check`. Bind consent
to the current reviewed proposal, source, preview, lost scenarios and named
stages. Pending, refused, withdrawn or changed scope cannot inherit old consent;
benefit alone cannot authorize disabling, consolidation or deletion. Prepare
evidence, consumer/installation impact, alternatives, retained checks and
restoration before asking. Do not repeatedly prompt an unchanged refusal.

After the A-on-B decision, retain the independently checked B solutions and
select one exact B candidate for B-on-C. An A rejection keeps H unchanged;
another valid B solution is a different candidate. Preserve rejected
experiment specifications without synchronizing their unadopted requirements.
An experiment outcome does not close unfinished required OpenSpec work.

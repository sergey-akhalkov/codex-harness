## Shell output

For verbose native commands, use `harness-rtk.exe exec git log -n 80` (or `git status --short`, `rg -n`, `pytest`, `python -m pytest`, `uv run pytest`). The accepted hook changes only this entry mode to `compact`; the adapter executes the native program once and filters what it captured. It forwards actual arguments, cwd, environment, stdin, both streams and the exit status. It intentionally selects a native executable, so use ordinary shell calls for shell functions/aliases. Codex omits the chosen shell from hook input; ordinary commands are therefore unchanged. Never retry to satisfy a hook. Automatic diagnostics and Stop hooks remain inactive.

Human-output `cargo test`, `cargo check`, `cargo build` and `cargo clippy` are covered, including package/workspace selection, `--locked`, job limits and arguments after the Cargo separator, for example `harness-rtk.exe exec cargo check -p my-crate --locked --jobs 1`. Cargo writes progress and rustc diagnostics to stderr, so both streams are handled: each is decided on its own, recognized Cargo status lines leave the presentation, every other line stays verbatim, and a compacted run whose child failed also prints `[rtk cargo exit: <code>]`. `--message-format json`, `--json`, verbose output, unknown flags, other Cargo verbs and `--nocapture` stay raw, as do streams below 500 bytes, non-shrinking results, filter failures and captures above 4 MiB per stream (which continue live without retention). While a long run is held back for presentation, a bounded progress notice reports captured bytes; `HARNESS_RTK_PROGRESS_SECONDS` sets its spacing and `0` disables it.

A compressed stream includes an `rtk raw` file locator and a packed observation line with a stable handle and digest; the stderr stream names itself (`rtk raw[stderr]`, `rtk pack[stderr]`). Recover needed detail through the bounded window first: `harness-rtk.exe recall <handle> --offset N --limit M` returns digest-verified, numbered lines with provenance — including which stream they came from — without executing the command again. Use the whole `rtk raw` file only when the complete content is genuinely required. Packed observations live locally, survive the creating session and are evicted oldest-first beyond 64 records or 128 MiB; storage keeps up to 32 raw captures of at most 4 MiB each; larger output passes raw. A locator is local evidence, not a durable report. For exact source, a final review diff, machine output or an exhaustive search, use the original command without the prefix. `HARNESS_RTK_DISABLE=1` bypasses compression; an already explicit `compact` call is never rewritten. Interactive output and unsupported actual arguments pass raw without a footer. Do not infer complete coverage from a shortened list. A filter failure leaves raw output usable with a diagnostic.

`harness-rtk.exe diagnostics [--last N] [--json]` reads the bounded local decision records for an explicitly inspected invocation: applied versus bypassed, the concrete reason, measured raw and delivered bytes per stream and the complete presentation size. `HARNESS_RTK_DIAGNOSTIC=1` prints the same evidence for the current run on stderr. Those are bytes, never token, subscription or quota measurements; the token field stays unavailable.

Use RTK's broader explicit commands only when their runner/format behavior fits the task. In particular, keep the selected Python/uv environment. `rtk gain` uses estimates; it is not a measure of session or subscription savings.

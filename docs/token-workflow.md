# Экономия токенов в рабочем процессе

RTK и native Code Mode подключены глобально и проверены свежими потребителями вне репозитория. Принятый процесс также включает точную навигацию Serena/CBM, `apply_patch`, повторное использование актуальных результатов и reasoning по сложности задачи. [Изменение](../openspec/changes/archive/2026-09-08-optimize-agent-token-workflow/proposal.md) реализовано и архивировано; измерения и ограничения находятся в [отчёте приёмки](evidence/token-workflow.md). Уже работающим сессиям нужен новый запуск для обнаружения изменённой конфигурации.

RTK — явное пользовательское исключение к режиму без обычных хуков. Для объёмного вывода агент вызывает, например, `harness-rtk.exe exec git log -n 80`; выбранный `PreToolUse` меняет только режим адаптера на `compact`. Нативная программа выполняется один раз с фактическими аргументами, cwd и окружением; фильтруется только stdout. Stderr и код завершения сохраняются. Codex 0.153.4 не передаёт выбранную оболочку хуку, поэтому обычные команды не переписываются: это сохраняет shell-функции и aliases. Подробности доступны по указателю `rtk raw`; повторный запуск не требуется. Неоднозначный shell-синтаксис, неподдерживаемые/машинные форматы и `HARNESS_RTK_DISABLE=1` обходят сжатие. `global/hooks.json` и прежний диагностический обработчик остаются неактивными; определение RTK находится отдельно в `global/rtk-hooks.json`.

Подробное использование хранится в одном переносимом [skill](../.agents/skills/token-efficient-workflow/SKILL.md). Он загружается для задач с существенным объёмом вывода, повторных чтений или выбора effort. Code Mode позволяет обработать промежуточные результаты до передачи в контекст, но не оправдывает потерю ошибок, пропуск покрытия или повторную индексацию неизменившегося кода. Маленькие правки по-прежнему выполняются обычным коротким путём.

Для новой задачи launcher принимает первым аргументом `--harness-effort routine|standard|demanding`, что задаёт native `low|high|xhigh`. Явный native effort/profile имеет приоритет; обычный старт сохраняет `xhigh`. Изменение effort внутри уже работающего хода инструмента текущего CLI не поддерживается. Внешний app-server клиент может задать `turn/start.effort` для следующего хода. Имена усилий не доказывают процент экономии. Grok middle, Astra-резерв и границы эскалации сохраняются.

Установка использует RTK 0.48.0 для Windows x64 с закреплёнными SHA-256 архива и exe. Для сборки небольшого адаптера нужен Cargo/Rust; исходники находятся в `tools/rtk-adapter`, артефакты с идентичностью сборки — вне Git, в `CODEX_HOME/harness/rtk`. Подключение бинарников и определения хука выполняется ссылками. Native trust привязан к фактическому определению; глобального обхода доверия нет.

Для первичного доверия запускайте исходный CLI из поля `codexCommand` в `CODEX_HOME/harness/installation.json` без `--profile`, затем проверьте единственное определение `harness-rtk.exe hook` в окне review или `/hooks`. Так native editor сохраняет машинный hash в базовом конфиге; выбор связанного профиля при review может записать его в исходный файл профиля. Приёмочный скрипт `tests/token-workflow-native.ps1 -TrustHook` использует базовый consumer и проверяет фактический `trustStatus` новым соединением.

```powershell
./install.ps1 -TokenWorkflowOnly             # после установки core
./install.ps1 -TokenWorkflowOnly -Mode Check
./install.ps1 -TokenWorkflowOnly -Mode Update
./install.ps1 -TokenWorkflowOnly -Mode Disconnect
./install.ps1 -TokenWorkflowOnly -Mode Recover # при сохранённой незавершённой транзакции
```

Обычная полная установка включает выбранную возможность. Свежий `-CoreOnly` оставляет хуки выключенными. Повторная установка сохраняет ручное native-отключение; для повторного включения принятой возможности после такого отключения можно использовать `codex features enable hooks`. Отключение компонента снимает его ссылки и не восстанавливает старые диагностические хуки. Общие внешние пакеты и записи вывода не удаляются автоматически. Code Mode, включённый до подключения компонента, сохраняется при отключении.

Источники runtime-контрактов: [RTK 0.48.0](https://github.com/rtk-ai/rtk/releases/tag/v0.48.0), [native hooks](https://learn.chatgpt.com/docs/hooks), [настройки Codex](https://learn.chatgpt.com/docs/config-file/config-reference). Заявления RTK о 60–90% относятся к поддерживаемому выводу. `rtk gain` оценивает токены через объём текста; это не наблюдение расхода всей сессии или недельной квоты.

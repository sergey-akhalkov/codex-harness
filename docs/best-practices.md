# Практики скорости и качества

[Карта документации](README.md) · Срез: 2026-09-06

Это выводы из официальных источников и предложения для развития `codex-harness`. Они помогают принимать решения. Состав первой реализации прямого подключения и его настройки перечислены в [инструкции установки](installation.md); остальные предложения сохраняют исследовательский статус.

При их применении учитывать [подтверждённую философию и решения проекта](project-decisions.md): результативность, отсутствие P0/P1 как цель качества, скорость до полного результата, OpenSpec по умолчанию и выполнение всей согласованной спеки с закрытием всех задач как критерий завершения.

## 1. Определять проверяемый результат

В постановке задачи указывать цель, полезный контекст, ограничения и признак завершения. Для ошибки особенно полезны шаги воспроизведения и ожидаемое поведение. Сложную или неоднозначную задачу сначала прояснять. [Best practices](https://learn.chatgpt.com/guides/best-practices), [Prompting](https://learn.chatgpt.com/docs/prompting)

Предложение для harness: шаблоны задач должны помогать задать эти данные без обязательной большой анкеты для каждой мелкой правки.

## 2. Держать постоянные инструкции короткими

В `AGENTS.md` оставлять устойчивые соглашения и маршруты к подробностям. Правила уточнять по повторяющимся наблюдаемым ошибкам. [Best practices](https://learn.chatgpt.com/guides/best-practices)

Codex собирает глобальные и проектные инструкции в определённом порядке, с overrides и ограничением размера. Ссылка на документ не означает, что весь документ автоматически включён в контекст. [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

Применение: корневой `AGENTS.md` этого репозитория — краткая инструкция его разработчику; [переносимые рабочие принципы](../global/principles-of-work.md) имеют отдельный источник и [глобальное подключение](global-instructions.md).

## 3. Загружать специализированные знания по задаче

Skills сначала представлены метаданными; полный `SKILL.md` читается при применении. Описания определяют срабатывание. Каждому skill нужны конкретная задача, входы, выходы и понятные условия использования. Скрипт оправдан, когда требуется детерминированная операция или внешнее средство. [Build skills](https://learn.chatgpt.com/docs/build-skills)

Предложение: проверять как подходящие запросы, так и похожие запросы, на которых skill не должен срабатывать. Большой установленный каталог тоже имеет стоимость discovery.

## 4. Настраивать поведение под модель и задачу

Актуальное model guidance отдельно рассматривает автономность, влияние инструкций из файлов, делегирование и склонность к избыточной проверке. Переносимые prompts нужно пересматривать при смене модели. [Model guidance](https://developers.openai.com/api/docs/guides/latest-model)

В Codex выбирать модель и reasoning по сложности и результатам проверки. Fast mode имеет отдельные ограничения доступности и расхода. [Models](https://learn.chatgpt.com/docs/models), [Speed](https://learn.chatgpt.com/docs/agent-configuration/speed)

Предложение: сравнивать несколько настроек на одинаковых задачах. Постоянные максимумы reasoning, численности агентов и набора инструментов пока не являются принятым решением.

## 5. Делегировать независимые части работы

Subagents полезны для ограниченного исследования, проверки и анализа с возвратом краткого результата. Они имеют стоимость собственных model/tool вызовов. Инструкции должны определять, когда нужна делегация; основной агент сохраняет ответственность за интеграцию. [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)

Предложение: учитывать пересечение файлов, цену передачи контекста и сборки результата. Изолировать параллельные изменения через подходящие Git worktrees; управление ими из app и самостоятельное использование Git — разные пути. [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees)

## 6. Добавлять инструменты под конкретную потребность

Начинать с интеграций, которые устраняют повторяющуюся ручную работу. [Best practices](https://learn.chatgpt.com/guides/best-practices)

Для MCP задавать ясные tool-контракты и описания, возвращать пригодный для дальнейшего действия результат. В Codex доступны фильтры инструментов и настройки таймаутов. [Define tools](https://developers.openai.com/plugins/plan/tools), [MCP](https://learn.chatgpt.com/docs/extend/mcp)

Предложение: оценивать время запуска сервера, точность навигации, задержку tool calls и пользу для проверки кода. OpenAI Docs MCP — кандидат для доступа к актуальным первоисточникам. [Docs MCP](https://developers.openai.com/learn/docs-mcp)

## 7. Проверять изменение соразмерно его последствиям

Model guidance рекомендует завершать нужные проверки и расширять их, когда новые изменения, ошибки или нерешённые вопросы это оправдывают. Для небольших обратимых изменений дополнительные тесты должны иметь содержательную ценность. [Model guidance](https://developers.openai.com/api/docs/guides/latest-model)

Для coding workflow нужны доступные команды воспроизведения, проверки и review. [Prompting](https://learn.chatgpt.com/docs/prompting), [Code review](https://learn.chatgpt.com/docs/code-review)

Предложение: фиксировать наблюдаемое поведение и существенные ограничения; использовать команды конкретного проекта через его инструкции или адаптер.

## 8. Измерять пользу изменений harness

Официальный материал об оценке skills предлагает проверять результат, процесс, стиль и эффективность. Полезны явное, неявное, контекстное срабатывание и отрицательный пример; трассы помогают находить лишние команды и регрессии. [Testing Agent Skills Systematically with Evals](https://developers.openai.com/blog/eval-skills)

Предлагаемая проверка каждого существенного усиления:

| Что сравнивать | Как интерпретировать |
| --- | --- |
| Завершение принятой задачи | Главный признак полезности |
| Корректность и регрессии | По наблюдаемому поведению и подходящим проверкам |
| Время до первого полезного сигнала | Скорость обнаружения воспроизведения, диагноза или рабочего пути |
| Время до проверенного результата | Полная длительность с проверкой и исправлениями |
| Лишние команды, повторы и вмешательства | Источники задержки |
| Токены и стоимость | Дополнительная цена достигнутого качества |

Это наша предлагаемая система оценки, а не обещанные OpenAI ускорения. Сравнивать baseline и кандидат на одних задачах, в сопоставимом окружении; учитывать вариативность агентных запусков.

## 9. Сохранять состояние длительной работы

Goals предназначены для устойчивой цели с критерием завершения, а память помогает переносить полезный контекст. Обязательные правила должны оставаться в управляемых инструкциях и документах. [Using Goals](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex), [Memories](https://learn.chatgpt.com/docs/customization/memories)

Предложение: перед переносом собственных механизмов продолжения и памяти из `opencode-kit` проверить, какие потребности уже закрываются возможностями Codex. Сопоставить условия завершения, восстановления, остановки и доступность в целевой версии.

## 10. Различать поддерживаемую возможность и пример её применения

Статья или Cookbook показывает подход для конкретного окружения. Например, recipe с `GOALS.md`, `PLANS.md` и фазами прямо обозначает дополнительные файлы как соглашения workflow. [Iterating development workflows](https://developers.openai.com/cookbook/examples/codex/iterating-development-workflows-with-codex)

Предложение: переносить доказанно полезный приём с минимальным необходимым набором артефактов.

## 11. Использовать подходящий слой интеграции

Для глобальных предпочтений есть конфигурация и инструкции; для повторяемых задач — skills; для tools — MCP; для упаковки — plugins; для событий — hooks. Программная автоматизация доступна через `codex exec` и SDK, глубокая клиентская интеграция — через App Server. [Customization](https://learn.chatgpt.com/docs/customization/overview), [Plugins](https://learn.chatgpt.com/docs/build-plugins), [Hooks](https://learn.chatgpt.com/docs/hooks), [SDK](https://learn.chatgpt.com/docs/codex-sdk), [App Server](https://learn.chatgpt.com/docs/app-server)

Предложение: выбирать самый простой поддерживаемый слой, который обеспечивает нужное поведение. OpenCode TypeScript plugins требуют адаптации к контрактам Codex.

## 12. Отдельно применять рекомендации для собственного API runtime

Сокращение лишней генерации и запросов, параллельная независимая работа и детерминированные операции помогают уменьшать задержку. [Latency optimization](https://developers.openai.com/api/docs/guides/latency-optimization)

Prompt caching, tool search и API compaction имеют собственные контракты и зависят от модели. Их параметры нельзя автоматически переносить в `config.toml`. [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching), [Tool search](https://developers.openai.com/api/docs/guides/tools-tool-search), [Compaction](https://developers.openai.com/api/docs/guides/compaction)

Предложение: возвращаться к этому маршруту, когда потребуется писать собственный API runtime; для CLI сначала проверять его документацию и настройки.

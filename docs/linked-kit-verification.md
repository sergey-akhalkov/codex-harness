# Приёмка прямого подключения Codex

[Установка](installation.md) · [Consumer probes](linked-kit-probes.md)

Дата: **2026-09-06**. Среда: Windows native, Codex CLI **0.153.4**,
PowerShell **7.6.5**, OpenSpec **1.12.0**. Проверки относятся к этой версии
и точке входа CLI. Поддержка desktop/IDE не выводится из их результатов.

Набор активирован на текущем ПК и проверен через реальный глобальный вход.
Пользователь подтвердил допустимость машинных записей в общем конфиге;
приёмка учитывает эту согласованную границу.

## Реальная глобальная активация

Запущены `install.ps1 -WhatIf`, `install.ps1`, `install.ps1 -Mode Check`
и повторный `-WhatIf` на настоящем пользовательском окружении. Итог —
`Connected`, десять связей: девять добавлены, существующая правильная ссылка
на полный текст принципов принята без изменения её прежнего владения.
Повторный preview показал ноль операций и отсутствие изменения PATH.

| Объект | Фактический путь / результат |
| --- | --- |
| Источник набора | `D:/home/sergey-akhalkov/codex-harness` |
| Codex home | `C:/Users/noilw/.codex`; весь checkout не является CODEX_HOME |
| Обычный `codex` в свежем PowerShell | `C:/Users/noilw/.codex/harness/bin/codex.ps1` → `tools/codex.ps1` |
| Общий профиль | `C:/Users/noilw/.codex/harness.config.toml` → `global/harness.config.toml` |
| Глобальный AGENTS | `C:/Users/noilw/.codex/AGENTS.md` → полный `global/principles-of-work.md` |
| Skills | Шесть ссылок в `C:/Users/noilw/.agents/skills`; API возвращает исходные `.agents/skills/<name>/SKILL.md` из checkout |
| Агенты | `C:/Users/noilw/.codex/agents/codex-harness` → `global/agents`; производственных TOML-ролей — 0 |
| Разрешения новых обычных сессий | `approval_policy = "never"`, `sandbox_mode = "danger-full-access"` |

Настоящие свежие PowerShell-процессы с пользовательским и системным PATH
запустили обычный `codex` без `--profile` в нейтральном каталоге и отдельном
Git-проекте. Полный глобальный текст, проектные инструкции и проектный
конфиг загрузились вместе. `skills/list` вернул по шесть уникальных исходных
skills в нейтральном каталоге, отдельном проекте и самом harness.

Первый запуск обнаружил ошибку в тестовом аргументе доверия: dotted key
с кавычками не включал доверие, поэтому проектный AGENTS читался, а его
конфиг — нет. Исправлен только тест: полная inline TOML-таблица `projects`
передаётся как сессионный override. После исправления все 62 проверки
прошли; постоянные записи доверия для тестового проекта не создавались.

Проверены сохранность реальных config/auth/history, metadata, исходников
и наличие местного user-config слоя. На этом host не было скалярных ключей
из безопасного списка дополнительной проверки; их эффективность здесь
не заявляется. Совместное чтение специфических локальных настроек доказано
отдельными consumer fixtures. Модельных запросов при активации не было.

## TUI и сохранение настроек

В дополнительном настоящем `/model` изменён reasoning `xhigh → high`.
Для этой записи использовался отдельно созданный синтетический связанный
профиль во временном каталоге. Codex изменил его исходник; ссылка сохранилась,
локальная база осталась идентичной. SHA-256 настоящего профиля репозитория
не изменился. Выбор не содержал явно указанного файла назначения.

Отдельная настоящая проверка доверия подтвердила тот же путь записи. В новом
временном Git-репозитории выбран `Yes, continue` в TUI. Машинный путь с
`trust_level = "trusted"` появился в синтетическом связанном профиле;
`profileChanged=True`, `baseChanged=False`, `machinePathInProfile=True`.
Использовано только сессионное `-c windows.sandbox="unelevated"`, чтобы
не запускать настройку Windows sandbox. `/quit` завершился с exit 0,
реальный профиль репозитория сохранил SHA-256, временное дерево удалено.
Модельных запросов и глобальной настройки sandbox не выполнялось.

Эти результаты нельзя приравнивать к default-target API writer из consumer
suite: он пишет в локальную базу. Дополнительный разбор исходников именно
`rust-v0.153.4` объясняет этот результат: TUI назначает профиль своим
`user_config_path`, а local onboarding передаёт запись доверия проекту
тому же универсальному writer. Из этого следует запись машинного пути
доверия в общий профиль, что подтвердилось исполнением; первоначальное утверждение о локальном хранении
trust было подтверждено только для exec и отдельного API-процесса.

Источники точной версии: [выбор пути TUI](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/tui/src/startup_orchestration.rs#L62),
[writer TUI](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/tui/src/config_update.rs#L158),
[выбор файла сервером](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/app-server/src/config_manager_service.rs#L218),
[trust onboarding](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/tui/src/onboarding/onboarding_screen.rs#L641).
**Принятое решение пользователя, 2026-09-06:** машинные записи, включая пути
доверенных проектов, допустимы в общем конфиге репозитория. Спецификация
обновлена под эту границу: сохраняется штатная запись через ссылку,
авторизация/история/кэши/метаданные установщика остаются на host. Собственная
сборка Codex и разделение read/write targets не нужны. Запрет копирования
развёртываемых артефактов сохраняется.

Сырые ETX-байты Ctrl+C не завершили TUI в ConPTY-диагностике. Причина не
установлена, native baseline не доказан. Проверены штатный `/quit` и реальная
остановка дочернего процесса при остановке PowerShell pipeline; это границы
свидетельств о cancellation.

## Ревью и восстановление

Независимое ограниченное ревью обнаружило риски одновременной установки,
фиксации metadata до финальной consumer-проверки и обхода launcher более
ранним Machine PATH. Исправлены: mutex по пользователю и защита reentry,
общая транзакция до успешного старта и проверка порядка команды в новом
процессе. Журнал recovery проверяет допустимые пути и прежнее владение,
rollback PATH сохраняет чужие параллельные правки. Регрессии проверены
отдельными процессами и инъекциями ошибок.

Это ревью конкретных путей глобальных изменений и forwarding, а не аудит
всех возможных будущих TOML/skill-определений или внешних клиентов.

Другой аккаунт моделировался через отдельные UserHome/CodexHome в текущей
учётной записи. Несовместимая версия CLI и отказ права создания ссылки
инъецировались; нормальная загрузка и отказ на повреждённом TOML проверены
настоящим CLI. Inline формы локальных agent declarations проверены
регрессиями наряду с обычными таблицами.

## Очистка

Успешные consumer, installer и TUI прогоны сняли временные регистрации;
тестовых capabilities в глобальных каталогах пользователя не оставлено.
Исходные конфиги и авторизация сохранены.

Автоматическая проверка отклонила удаление следующих сохранённых
диагностических каталогов с сообщением `blocked by policy`, без подробной
причины. Повторных попыток обойти отказ не предпринималось. У трёх TUI
каталогов ссылки уже сняты; это остаточные диагностические файлы вне kit.

# Проверки реального потребителя linked kit

Дата: **2026-09-06**. Проверены **codex-cli 0.153.4**, Windows native, **PowerShell 7.6.5**. Этот документ описывает изолированные проверки; фактическая глобальная активация и принятое поведение profiled TUI writers учитываются в [отчёте приёмки](linked-kit-verification.md).

Исполняемый набор: [consumer.Tests.ps1](../tests/consumer.Tests.ps1), штатный JSON-RPC клиент для проверок: [consumer-rpc.ps1](../tests/consumer-rpc.ps1). Параметр `-NativeCodex` принимает абсолютный путь установленного `codex.exe`.

```powershell
./tests/consumer.Tests.ps1 -NativeCodex $nativeCodex
# Дополнительно: три ограниченных модельных запроса для проверки агентов.
./tests/consumer.Tests.ps1 -NativeCodex $nativeCodex -RunAgent -AuthSource $authFile
```

Обычный запуск не отправляет модельные запросы. `-RunAgent` связывает существующий файл авторизации с изолированным `CODEX_HOME`, не читает и не печатает его содержимое. Путь авторизации задаётся явно. По умолчанию временные регистрации удаляются без перехода по ссылкам; `-KeepProbe` предназначен для отладки и оставляет временный каталог, что явно сообщается.

В изолированном Windows-процессе замена `HOME` и `USERPROFILE` не заставила Codex читать `<временный пользователь>/.agents/skills`. Для изоляции этот набор использует фактически работающий пользовательский путь `<CODEX_HOME>/skills`. Это **не** свидетельство проверки установленного пути настоящего пользователя `~/.agents/skills`: его отдельно проверил набор `global-activation.Tests.ps1` после реальной установки, как записано в отчёте приёмки. Ссылки на те же исходники и нативное устранение дублей проверены обоими штатными потребителями.

## Агенты и ресурсы

Обнаружено существенное отличие двух типов регистрации в 0.153.4:

- Символьная ссылка на отдельный TOML-файл в `<CODEX_HOME>/agents` не обнаружилась: реальная попытка запуска вернула `agent type is currently not available`.
- Символьная ссылка на дочерний **каталог** внутри `<CODEX_HOME>/agents` обнаружилась рекурсивно. Реальный агент из него вернул `DIRECTORY_FIXTURE_OK`. Рядом находился обычный пользовательский агент, который отдельно успешно вернул `ORDINARY_FIXTURE_OK`.
- Прямой `-c agents.<name>.config_file='<source.toml>'` также позволил запустить определение из исходника без скопированного описания. В реализации выбран более простой вариант с дочерним каталогом `agents/codex-harness`.

Набор модельных проверок подключил [тестовый каталог](../tests/fixtures/consumer-agent.toml) дочерней ссылкой. Агент прочитал [ресурс](../tests/fixtures/consumer-agent-resource.txt) через эту ссылку и вернул **`AGENT_V1:RESOURCE_V1`**. В двух следующих процессах определение отдельного временного агента изменили, сохранив ссылку: ответы изменились с **`LIVE_AGENT_V1`** на **`LIVE_AGENT_V2`**. JSONL каждого запуска содержал завершённый вызов инструмента взаимодействия с агентами и ожидаемый финальный ответ.

Ресурс в этой проверке читается инструментом агента из указанного вызывающим кодом каталога. Это не утверждение о загрузке произвольных относительных полей TOML: проверяется конкретный способ использования ресурса. Все роли здесь — fixtures; набор не объявляет поставку производственного каталога агентов.

## Результат и границы

Модельный запуск прошёл **19 проверок**. После добавления отдельного сценария изменения глобальных инструкций обычный запуск прошёл **18 проверок**. В сумме подтверждены все **20 различных assertions**, которые содержит текущий набор с `-RunAgent`. Обычный повторный запуск завершился штатной очисткой временного дерева, не затронув внешние источники ссылок. Два сохранённых исследовательских каталога, включая модельный запуск с `-KeepProbe`, после извлечения результатов также удалены ограниченной очисткой без перехода по ссылкам. Тестовые регистрации агентов и ссылка на авторизацию удалены; исходники checkout и файл авторизации сохранены.

Попытка использовать PTY через инструмент выполнения завершилась до старта Codex ошибкой `CreateProcessW`, OS `-1073283067`. Поэтому сохранение выбора модели и доверия здесь проверено через настоящие штатные методы app-server, схему которых сгенерировал установленный CLI. Это эквивалент проверки runtime writer, а не проверка кликов или команд `/model` в TUI. Отображение TUI, запуск через установленный launcher и глобальная активация требуют собственной записи результатов.

## Контракты источников

- [Advanced Configuration](https://learn.chatgpt.com/docs/config-file/config-advanced): файловые профили, порядок наложения и локальный `CODEX_HOME`; профиль ниже проектных настроек и CLI overrides.
- [Build skills](https://learn.chatgpt.com/docs/build-skills): пользовательские/проектные пути и поддержка ссылок на каталоги skills. Устранение дублей одного канонического исходника выше — наблюдение установленного CLI.
- [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents): самостоятельные TOML-определения, обязательные поля `name`, `description`, `developer_instructions`. Работа дочерней ссылки на каталог выше проверена исполнением.
- [App Server](https://learn.chatgpt.com/docs/app-server): `skills/list`, `config/value/write` и `config/batchWrite`. Для точных полей запросов использовался также `codex app-server generate-json-schema --experimental` именно версии 0.153.4.

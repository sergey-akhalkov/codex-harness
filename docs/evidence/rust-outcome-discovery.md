# Native outcome discovery

2026-09-09. `codex-harness outcome-discover --request PATH` performs the fixed,
model-free native `initialize`, `skills/list` and `config/read` exchange. The
[implementation](../../crates/codex-harness/src/outcome_discovery.rs) and
[transport](../../crates/codex-harness/src/outcome_discovery_rpc.rs) replace the
discovery portion of the outcome helper. [Arm preparation](rust-outcome-arm.md)
now consumes it; suites/oracles, remaining consumers and global migration are
still unfinished under task 7.3.

The strict JSON request requires `case_root`, `codex_home` and an absolute
original native `upstream` executable. Case and home must be distinct existing
temporary directories outside the checkout. Optional `timeout` is 1–300 seconds
(default 30); `output_limit` is 1 KiB–64 MiB per stream (default 16 MiB).
`extra_config` uses the executor's route/authentication/model override rejection.
There is no prompt, thread start or arbitrary RPC method. Output JSON and raw
evidence are private: native configuration and skill paths are not redacted.

The child joins a 512 MiB, 50% CPU Windows Job before it resumes. The client
bounds requests, response records and output, applies a deadline, and cleans
owned descendants even after a normal root exit. Acceptance requires exit zero,
the selected native home/platform in initialization, exactly the expected ordered
responses, complete skill discovery for the requested cwd, and valid response
shapes. The full retained transcript is checked after shutdown, so a duplicate
error or malformed trailing record cannot hide behind the last valid response.
Notifications remain allowed; unexpected server requests fail closed.

The selected native executable hash and base/profile file snapshots must remain
unchanged. Snapshots check bytes and ordinary file identity; declared config
links additionally retain their resolved target. A missing base config is not
created by this helper. This is an endpoint consistency check, not an atomic
snapshot of all project/skill inputs or proof that an input never changed and
changed back. CLI 0.153.4 does not expose the file profile through `config/read`;
profiles with relevant skill/project discovery overrides are rejected. The
accepted scope is explicitly `native-base; profile has no discovery overrides`.

Protocol schemas were generated by the exact installed Codex 0.153.4 binary
using `app-server generate-json-schema --experimental`. Its SHA-256 was
`444A3F0008050605CAE73CD9B7A2DCAC61294062DFAAB56DD20430FD6498518B`.
The generated initialization, skill and configuration schemas and their hashes
are retained with the private acceptance evidence; no current generic schema
is substituted for this installed contract.

The [Rust integration tests](../../crates/codex-harness/tests/outcome_discovery.rs)
passed ten default cases covering protocol order, wrong home/cwd, malformed and
incomplete responses, late errors/requests, nonzero exit, EOF/deadline/output
limits, descendant cleanup, profile controls, absent config and changed inputs.
Mutation cases include changed bytes, same-byte object replacement, a newly
appearing config, a retargeted profile link and an altered executable. Two
counterexamples first failed against the old implementation: trailing errors
were accepted, and initialization from the wrong home was accepted. Both now
fail closed. Private fixture errors are retained without leaking through the
public failure message.

An explicit ignored test also passed against installed CLI 0.153.4 from an owned
outside-checkout home, discovering its test skill and Astra configuration while
preserving the base config. It made no model call and copied no authentication.
The final run took 14.96 seconds; this is acceptance duration, not comparative
performance evidence. Twelve executor and five launcher integration tests,
four core config snapshot tests, scoped formatting, Clippy and explicit Serena
error/warning diagnostics passed for the affected code.

```text
cargo test -p codex-harness --test outcome_discovery --test outcome_run --test native_launcher --offline --locked --jobs 1 --target-dir <owned-check-target> -- --nocapture --test-threads=1

cargo clippy -p harness-core -p codex-harness --all-targets --offline --locked --jobs 1 --target-dir <owned-check-target> -- -D warnings
```

The native test additionally requires `HARNESS_NATIVE_CODEX` set to the explicit
original executable. Commands run from this checkout with the existing private
parent check target. Logs, source hashes and generated schemas are retained in
`%LOCALAPPDATA%/codex-harness-evidence/outcome-discovery-36cfeda40bbb4b7f9835764232853849/`.
`accepted-integration.*`, `native-accepted.*` and `clippy-accepted.*` contain the
final results. `trailing-before.*` and `initialize-home-before.*` retain the
failing counterexamples. The final native raw receipt is under
`%TEMP%/codex-outcome-discovery-7C5HJ8/`. These checks did not activate the global
native kit or run excluded opencode-kit evaluations.

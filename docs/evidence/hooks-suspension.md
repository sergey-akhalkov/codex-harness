# Global hook suspension

[Documentation map](../README.md) · [User decision](../project-decisions.md#расход-подписки-и-условная-автоматизация) · [Optimization plan](../../openspec/changes/archive/2026-09-08-reduce-subscription-waste/proposal.md)

Verified on 2026-09-08 on the current Windows host: all configured hooks are
disabled, and cached command/MCP diagnostic handlers return without diagnostic
output. This is the immediate user-requested suspension, not completion of the
optimization plan or evidence of a particular weekly-quota saving. Explicit
diagnostics/navigation remain callable pending benefit assessment.

## Changes and recovery state

- The live `~/.codex/hooks.json` link still targets `global/hooks.json`, whose
  contents are now `{"hooks":{}}`.
- `[features] hooks = false` is set in the host base configuration and the linked
  `global/harness.config.toml` profile. This is the native setting documented in
  [Codex Hooks](https://learn.chatgpt.com/docs/hooks), checked against CLI 0.153.4.
- A host-local `~/.codex/harness/hooks.suspended` marker gates `tools/hook.ps1`
  before journal/backend work and the shared broker's `hook` operation before
  analysis. Explicit `diagnostics` and `navigate` operations are unchanged.
- The old broker was retired gracefully with `broker.retire(timeout=30)` using
  the installed registry identity. It reported PID 17052 retired. The following
  broker hook request returned `{}`. No Codex session or subscription proxy was
  terminated.

Editing the definitions/settings alone did not suppress the active session's
already loaded handlers. The marker and handler guards close that observed gap.
The marker is outside Git; live definitions remain empty even without it.

Host-only backups are under `~/.codex/harness/backups/`:

- `hooks-suspended-20260908-142154.json`
- `config.toml.hooks-off-20260908-142500`
- `harness.config.toml.hooks-off-20260908-142500`

These are recovery evidence, not instructions to restore the old hooks.
Re-enabling requires the plan's accepted benefit evidence. A failing candidate
returns to hooks-off. Full install/update/repair/relocation preservation is an
open implementation task; the checks here establish the current activation.

The native app-server was created and closed by the existing
[`tests/consumer-rpc.ps1`](../../tests/consumer-rpc.ps1) helpers:
`Start-ConsumerServer $NativeExe $HostCodexHome $OutsideDirectory`, then
`Invoke-ConsumerRpc $server 'hooks/list' @{cwds=@($OutsideDirectory)}`, with
`Stop-ConsumerServer` in cleanup. `$NativeExe` was the 0.153.4 vendor executable
inside the installed `@openai/codex-win32-x64` package, not the kit launcher.

Command-handler acceptance used a child PowerShell process so native stdin was
actually supplied:

```powershell
foreach ($hookEvent in @('pre','post','stop')) {
    $result = '{}' | pwsh -NoLogo -NoProfile -File C:/Users/noilw/.codex/harness/bin/hook.ps1 -Event $hookEvent
    if ($LASTEXITCODE -ne 0 -or @($result).Count -ne 0) {
        throw "Suspended handler was not quiet: $hookEvent"
    }
}
```

An earlier attempt piped into the script inside the same PowerShell process and
failed parameter binding; it was a probe error and is not counted as a passing
hook check. The corrected child-process checks above passed. A stale broker
source identity was also observed during the transition and resolved by the
graceful retirement before acceptance.

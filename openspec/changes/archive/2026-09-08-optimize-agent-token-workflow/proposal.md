## Why

Large shell and MCP responses, repeated inspection and unnecessarily expensive reasoning consume context and delay useful work. The user selected six complementary improvements after research, explicitly accepting a fast RTK hook when it saves tokens without materially reducing quality or speed.

## What Changes

- Deliver RTK globally with a bounded, quiet native PreToolUse adapter for verified command forms, exact-output bypass and recoverable full output. Keep ordinary diagnostic and Stop hooks inactive.
- Enable and verify native Code Mode for orchestration, filtering and aggregation before results enter model context; preserve failures and access to details.
- Improve the existing Serena and Codebase Memory workflow and compact interfaces without losing source coverage, errors, semantic editing or explicit diagnostics.
- Prefer `apply_patch` for suitable scoped edits and deterministic generators for mechanical work, avoiding full-file regeneration.
- Reuse unchanged inspections and valid checks, batch independent operations and eliminate redundant tool actions while retaining freshness and acceptance checks.
- Select real native reasoning effort according to task complexity and risk. Preserve Astra-only OpenAI assignments, preferred Grok middle, explicit reserves and escalation; do not introduce Fast mode or a new billing route.
- Integrate the accepted selection with install, update, repair, relocation and disconnect. Verify actual fresh consumers outside this repository and record measured output/latency with their limits.

## Capabilities

### New Capabilities

- `token-efficient-agent-workflow`: Effective RTK, Code Mode, semantic retrieval, scoped edits, reuse and task-level reasoning, with quality and efficiency acceptance.

### Modified Capabilities

- `linked-global-kit`: Preserve the explicitly accepted RTK hook exception while retaining the ordinary hooks-off default and recoverable global lifecycle.

## Impact

Portable configuration and instructions, existing MCP proxies where evidence warrants changes, launcher/native task configuration, installer lifecycle, a pinned RTK external dependency, a small hook adapter, and focused tests/evidence. Existing `reduce-subscription-waste`, `bound-code-tools-resources` and native-workflow work are reused; rejected diagnostics, unrelated dirty changes, credentials and provider selection remain outside this change.

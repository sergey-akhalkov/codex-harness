## Why

GPT-6 Astra's official guidance calls for revisiting accumulated instructions: broad skill triggers, repeated prerequisites and unnecessary approval stops can impede complete delivery. This pack distributes those instructions globally, so the complete documentation and instruction surface needs a traceable audit and coherent adaptation.

## What Changes

- Audit all repository instruction and documentation surfaces against current applicable official OpenAI articles and guides for GPT-6 Astra; record coverage, applicability and unresolved source gaps.
- Adapt pack-owned principles, AGENTS guidance, skills, references, agent instructions and operating documentation: precise triggers, progressive disclosure, clear authority, persistence, concise communication, useful delegation and proportionate verification.
- Preserve confirmed user constraints, required acceptance, publication boundaries, active work and supported non-Astra consumers. Recommendations and examples are interpreted within their documented conditions.
- Keep OpenSpec instructions, skills, schemas, templates and workflow configuration unchanged. Record external conflicts without modifying or overriding externally maintained workflows. Project-owned requirements and change artifacts remain in scope.
- Verify changed instruction loading through the existing global lifecycle and exercise representative behavior; distinguish static consistency, observed loading and actual model behavior.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `global-working-principles`: Add official Astra guidance coverage, protected OpenSpec ownership, coherent adaptation and observable acceptance requirements across the pack's instruction/documentation surfaces.

## Impact

Expected edit surfaces include `global/principles-of-work.md`, `AGENTS.md`, pack-owned `.agents/skills/` and supporting resources, relevant `global/` agent instructions, `README.md`, `docs/`, and project-owned OpenSpec artifacts. Audit also includes instructions embedded in source, tests, examples, and archives; discovered executable changes require their applicable checks and explicit scope assessment rather than an incidental rewrite.

No new dependency, API/model migration, provider replacement, installation redesign, or publication is proposed. Existing global live links mean source edits can affect new sessions outside this checkout. Pre-existing working-tree changes and unfinished changes remain intact. This proposal authorizes planning only; implementation follows a separate user request.

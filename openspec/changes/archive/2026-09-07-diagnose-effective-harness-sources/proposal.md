## Why

Existing Check stops at broken installation links and probes a neutral directory. It cannot explain project-specific overrides or conflicting discovered skills, so users repeatedly reconstruct source precedence by hand. A model-free diagnostic has the highest immediate expected return among the audited recommendations: it addresses observed global activation and restart confusion using native read APIs and the existing installation lifecycle.

## What Changes

- Add focused diagnostics to `install.ps1 -Mode Check -Diagnose -ProjectPath <directory>` and a globally linked `codex-harness-check.ps1` entry point.
- Report managed link destinations and actual targets, native effective setting origins and overriding layers, and discovered skill name collisions with recovery advice.
- Distinguish observations in a newly started native consumer from declarations on disk and unknown state of existing sessions. Aggregate problems without exposing credentials or prompt bodies; perform no model calls or configuration repair.
- Correct material audit recommendations and document verification, actual measurement limits, and global use.

## Capabilities

### New Capabilities

- `harness-source-diagnostics`: bounded, private, model-free inspection of installation and project configuration sources through the global lifecycle.

### Modified Capabilities

None. Existing installation Check and its protocol checks remain available without `-Diagnose`.

## Impact

PowerShell diagnostic module and launcher, installation dispatch and link inventory, native consumer fixtures, installation documentation and evidence. No new dependencies, model profiles, background services, hooks or runtime replacements. Existing unrelated work is preserved and included in the requested final Git push.

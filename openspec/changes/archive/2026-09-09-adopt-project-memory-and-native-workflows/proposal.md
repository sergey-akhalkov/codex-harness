## Why

Повторное восстановление контекста и ручная передача результатов замедляют длительные задачи. Пользователь выбрал проектную память в Git, экспериментальное управление контекстом Astra, Git worktrees и структурированные запуски Codex. Проверка `/btw` проведена; 2026-09-08 пользователь подтвердил, что команда заработала.

## What Changes

- Поставить глобальный workflow чтения и ведения памяти **в Git каждого проекта**: короткий индекс, существующие записи решений и проверенные практические сведения, выборочное чтение и проверка актуальности. Использовать его в самом harness и проверить переносимость через другой репозиторий и свежий clone.
- Провести обратимый пилот `features.context_management.experimental_mode` для новых задач Astra, проверить реальную доступность и поведение, затем подключить выбранную настройку через штатный жизненный цикл набора.
- Сохранить результаты проверки `/btw` и `/side` и краткий маршрут использования. Пользовательский сбой закрыт по подтверждению пользователя; изменение feature flags и дальнейший поиск причины не требуются.
- Добавить глобальный workflow изолированных задач через обычные Git worktrees: явные исходные изменения, подготовка окружения, идентичность инструментов, интеграция и очистка своих ресурсов.
- Применять `codex exec --output-schema` для подходящих ограниченных задач с проверкой JSON, завершения процесса и независимых критериев результата; использовать существующие средства исполнения и проверки.
- Goals уже используются. Fast mode исключён по решению пользователя. Глобальные native memories и их фоновая генерация, отдельный оркестратор и обязательный дополнительный model call на каждую задачу в эту работу не входят.

## Capabilities

### New Capabilities

- `git-project-memory`: хранение, обнаружение, выборочное использование и актуализация проектной памяти в Git без зависимости от личной истории Codex.
- `native-context-workflow`: проверяемое использование экспериментального контекста Astra и совместимый workflow бокового вопроса в CLI.
- `isolated-worktree-workflow`: применение worktrees для подходящих независимых задач с сохранением исходных данных и проверкой интеграции.
- `structured-codex-runs`: ограниченные неинтерактивные запуски с машинно проверяемым итогом и честным статусом выполнения.

### Modified Capabilities

Нет. Новые возможности используют существующие требования `linked-global-kit` к глобальному обнаружению, прямым ссылкам, обновлению, отключению и сохранению чужих настроек.

## Impact

Предполагаемые точки поставки: `.agents/skills/`, `global/harness.config.toml`, существующие `global/kit.psd1` и установщик при необходимости регистрации, проектные `AGENTS.md` и документация. Данные памяти принадлежат целевому проекту; credentials, runtime, индексы и сырые логи остаются вне Git. Проверки расширяют подходящие существующие consumers и используют Windows ConPTY и средства наблюдения процессов из набора.

Совместимость: установленный Codex CLI 0.153.4, PowerShell 7.4+, обычный Git и действующая маршрутизация Astra/Grok. Возможности desktop app не считаются доступными в CLI автоматически. Bounded Git-память 1.3/1.4, Astra runtime pilot 2.1, ordinary runtime/false override/profile rollback 2.2, worktree и structured-run consumers уже имеют принятое evidence. Общая lifecycle-приёмка глобальных навыков пройдена; owning evidence — docs/evidence/native-workflows.md. Native memories и Fast остаются выключенными; ordinary diagnostic/context/Stop hooks не возвращаются.

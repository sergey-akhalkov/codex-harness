## Why

Полезные способы работы теряются между задачами, а накопление скиллов без проверяемой отдачи и без видимых вызовов расходует контекст. Нужна автономно поддерживаемая библиотека с полным циклом: появление и правка навыка, наблюдаемое использование, разбор роста и кандидатов на отключение, проверка и доставка принятого изменения в текущую сессию.

## What Changes

- Поставить один глобальный `skill-evolution`, использующий доступный `skill-creator`: создание, уточнение, объединение и вывод скиллов из использования по наблюдаемым результатам работы. Отделять процедурные навыки от фактов, предварительных идей и команд, у которых уже есть место в памяти или инструментах проекта.
- Автономно вести проектные скиллы в Git текущего репозитория, сохраняя чужие изменения. Общие навыки поставлять из одного канонического источника harness после проверки переносимости; черновики держать вне каталогов обнаружения.
- Сравнивать библиотеку до и после одного изменения: добавления, обновления, сокращения, объединения или отключения. Фиксировать модель, усилие, окружение и независимую приёмку; учитывать подходящие и неподходящие задачи, взаимодействие с соседними скиллами и неопределённость. Решения — принять, отклонить или сохранить текущую библиотеку из-за недостатка данных.
- Учитывать каталог, чтение инструкций, вызванные действия, ошибки, исправления и создание/проверку кандидатов. Ограничить объём управляемого активного каталога и общий расход обучения за период, а также каждый эпизод; не объявлять токены точным расходом подписки. Численные параметры определить первым ограниченным экспериментом на существующем скилле до автоматических решений.
- Запускать обслуживание по наблюдаемым событиям, рассматривать сокращение и обратимое отключение наравне с созданием. Черновики и выведенные пакеты не участвуют в discovery; редкое использование и нехватка контекста сами по себе не разрешают удаление. Защитить критерии приёмки от изменения самим кандидатом.
- Обеспечить обратимую активацию проверенной ревизии, обнаружение конфликтов, ограниченные повторные попытки и сохранение действующей версии при неуспехе. Обычное обслуживание в разрешённой области не требует ручного ревью каждого скилла.
- Добавить компактный производный каталог и доставку изменений в текущую сессию; восстановление после compaction/resume и передача актуального навыка субагентам входят в обязательную приёмку. Перезапуск сессии не считается заменой этого результата.
- Не вести incubator, голосование, квотный pacing аккаунта и замену оркестрового процесса через `codex resume`; это владение `orchestrate-feedback-and-pacing`. После accept/publish фиксировать компактную идентичность ревизии (`name`, canonical path, revision, операция) для таких потребителей — без шины событий и без подмены same-session compact перезапуском воркера.
- Вести локальный журнал наблюдаемых вызовов: как (явный `$` / неявное чтение body), где (проектный worktree или глобальный источник), кем (родитель или ребёнок в сессии) и когда был последний вызов. Каталожное присутствие не считается вызовом; отсутствие покрытия журнала не выдаётся за «никогда».
- Дать native команду `codex-harness skills usage`: в проекте сначала скиллы этого репозитория, затем только глобально доступные, без дубля одной канонической ревизии. Поставить глобальный `skills-usage-analysis`, который вызывает эту команду по запросу о росте/использовании/уборке и сразу предлагает кандидатов на отключение или удаление с причиной. Не запускать разбор на старте каждой сессии и не применять кандидатов без подтверждения.
- Подключить механизм через существующий lifecycle kit и проверить реальную работу в двух репозиториях вне harness, свежем clone и текущей сессии. Пилот является этапом приёмки всей системы; регистрация файлов или подготовка отчёта не означают завершения реализации.

## Capabilities

### New Capabilities

- `autonomous-skill-evolution`: отбор опыта, владение знаниями, обслуживание библиотеки по событиям, автономное изменение, обратимое отключение и перенос общих навыков.
- `skill-evaluation`: сравнение библиотек, три исхода решения, независимые испытания, полные затраты и бюджеты эпизода/периода.
- `skill-session-awareness`: измеряемый бюджет каталога, принятие и отключение ревизий в работающей сессии, восстановление и применение субагентами.
- `skills-usage-analysis`: журнал вызовов, команда разбора с проектными скиллами выше глобальных, отчёт о росте и кандидаты на отключение.

### Modified Capabilities

- `linked-global-kit`: расширить контракт обновлений для активируемых системой скиллов в работающих сессиях и добавить автономное согласование только принадлежащих kit регистраций без копирования исходников.

## Impact

Предполагаемые точки реализации: `.agents/skills/skill-evolution/`, `.agents/skills/skills-usage-analysis/`, native `codex-harness skills usage`, локальный журнал вызовов в runtime владельца установки, переносимая политика в `global/`, небольшое ядро решений и проверок на Rust в существующем workspace, manifest и lifecycle kit. Модели предлагают содержательные изменения; код проверяет входные данные, применяет фиксированные правила решения, учитывает бюджеты и защищает публикацию. Проверки переиспользуют подходящие consumers из `tests/`, включая native CLI, App Server и Windows TUI; App Server не подменяет основной CLI. Выбор proof-инструментов зависит от проверяемого свойства ядра; доказательство правил управления не является доказательством полезности текста скилла.

Ordinary diagnostic, context and Stop hooks remain OFF. `global/hooks.json` is empty ownership/relocation state, not an active diagnostic stack. The only accepted hook exception is the narrow RTK PreToolUse adapter. Same-session compact/resume skill recovery remains required; without a supported hooks-off delivery path it stays an owning blocker rather than a restored SessionStart/PostToolUse/Stop implementation.

Первая поставка этого change не утверждает принятого улучшения библиотеки и не заявляет net benefit. Правила `accept`/`reject`/`inconclusive` для последующих кандидатов сохраняются. Пользователь 2026-09-19 сузил закрытие change без claimed benefit.

Интеграция использует выбранную [проектную Git-память](../../../specs/git-project-memory/spec.md) без второго авторитетного хранилища; native memories remain excluded. Первый target остаётся установленный Windows Codex CLI, с PowerShell для shell и Rust для нового поддерживаемого исполняемого кода. Историческая проверка CLI 0.153.4 не заменяет проверки фактической версии перед реализацией.

Фоновый обход неактивных репозиториев, собственный оркестратор, incubator и голосование оркестрации, квотный pacing аккаунта, замена оркестрового процесса через `codex resume`, автоматический commit/push, перезапись сторонних или встроенных скиллов и самостоятельное изменение правил контроля в объём не входят. Intake таких сигналов и succession воркеров принадлежат `orchestrate-feedback-and-pacing`. Этот change содержит план; создание артефактов не активирует механизм и не запускает модельные испытания.

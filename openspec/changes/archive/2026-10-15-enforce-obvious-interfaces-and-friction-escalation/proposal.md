# Proposal

## Why

The principles already name "don't make me think", but do not explicitly make it a design obligation for every interface or clearly require timely escalation when a usable workaround conceals a materially poor workflow. Agents can therefore keep assembling prerequisites and recovery by hand while reporting progress, leaving the ordinary user path unnecessarily difficult or incomplete.

## What Changes

- Make obvious, low-burden use mandatory across UI/UX, CLI, API, methods, functions, libraries, configuration, tools, instructions and agent workflows, preserving correctness and authority.
- Judge the complete ordinary path, including setup, repetition, interruption and recovery, by required decisions and remembered mechanics rather than command count or the agent's ability to overcome difficulty.
- Require the owning interface to coordinate routine mechanics that it can reliably derive, validate and perform; retain explicit meaningful user choices and proportionate advanced control.
- Require early, concrete improvement proposals when material friction is discovered, even if work can continue. Distinguish an autonomous bounded correction, a reported systemic improvement and a decision requiring dependent work to pause.
- Preserve the user's informed choice, full acceptance and independent useful work; prohibit silent repeated workarounds, automatic scope expansion and repetitive suggestion noise.
- Consolidate the existing policy sections and verify source consistency, global delivery and observed behavior separately.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `global-working-principles`: universal interface ergonomics, observable lifecycle usability, and actionable friction reporting and escalation within the existing partnership and workflow contracts.

## Impact

Implementation affects `global/principles-of-work.md`, the existing global-working-principles specification, and the owning guidance in `docs/global-instructions.md` and `docs/project-decisions.md`. Delivery uses the existing linked global instructions and preserves unrelated settings. Existing source checks and representative external-use verification remain the acceptance route; no new evaluator framework, skill or mandatory report is introduced.

## Non-goals

- Repairing any consuming project, redesigning a particular stand or implementing an experiment launcher.
- Mandating one literal command, a universal facade, zero configuration or speculative automation.
- Weakening integrity, explicit effect boundaries, recovery, compatibility or required checks for convenience.
- Editing externally maintained OpenSpec workflows, changing model/provider policy or claiming guaranteed future compliance or efficiency gains.

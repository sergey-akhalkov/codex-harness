## Why

The kit duplicates some capabilities now supplied by Codex CLI and its dependencies, while several policy helpers have no established production consumer. Reduce maintained code and agent instructions without losing accepted behavior, introducing manual operating steps, or treating an unverified native substitute as equivalent.

## What Changes

- Consolidate executor control around native conversations, events and presentation, consuming the existing TUI and lead-message changes rather than adding another controller. Retain the small adapter for ownership, worktree bounds, visibility, reply holds, recovery and acceptance.
- Use native reasoning settings as the documented interface; preserve existing command compatibility without maintaining a second policy vocabulary.
- Use native skill discovery and supported MCP selection settings. Preserve revision/disablement evidence and remove conflicting or unavailable-tool guidance.
- Remove verified unconsumed helpers and duplicated mechanisms only after tracing their accepted rules to a real retained consumer. An unfinished requirement stays unfinished; deletion is not its implementation.
- Qualify specific replacement candidates in diagnostics, RTK, dependency management and provider compatibility. Remove equivalent duplicates; retain the smallest necessary adapter where a concrete gap remains. Keep live-link installation, resource control, independent result checks, measured analytics and safe disk reclamation.
- Shorten the affected owned instructions and command guidance alongside implementation. Measure production code separately from tests and measure complete instruction surfaces, including generated briefs and referenced mechanics; do not move bloat into another routinely loaded file.
- Deliver replacements through the existing global lifecycle and preserve active sessions, unrelated settings and rollback. No new runtime, registry, generic plugin framework or evaluation/reporting platform is introduced.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `rust-native-harness`: observable compatibility and evidence requirements for native substitutions and removal of unused mechanisms.
- `token-efficient-agent-workflow`: canonical native effort selection with compatible legacy input handling.
- `skill-session-awareness`: native discovery as the authority, with bounded kit-specific identity and awareness evidence.
- `global-code-tools`: effective native tool selection and guidance consistent with available tools.
- `agent-delegation`: shorter instructions backed by executable orchestration mechanics.

## Impact

Primary code owners are `crates/codex-harness`, `crates/harness-core`, `crates/skill-evolution` and `tools/rtk-adapter`; the existing tests and installation lifecycle remain the delivery path. Owned instructions and guides change only with their verified implementation. Externally maintained OpenSpec workflow files remain untouched.

The [design](design.md) assigns each audit recommendation and overlapping active change one owner and defines integration order. Existing native-TUI, lead-message, CPU-budget, failed-tab closure, cache-loss and xAI-startup requirements remain mandatory; this change does not reopen completed tasks or claim their unfinished acceptance.

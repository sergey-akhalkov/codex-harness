## Why

The repository is becoming `coding-agents-harness-pack`, a reusable public source of agent instructions, skills, MCP connections and installation tooling. Consumer-specific names and machine state currently enter tracked configuration, reports, tests and documentation, while repeated historical reports obscure the information needed to maintain the pack.

## What Changes

- Establish a public-source boundary for all tracked files and generated public output, including project memory and delegated work. Use synthetic examples and keep private acceptance inputs outside the repository.
- Remove consumer identifiers and machine-specific configuration without weakening existing real-project acceptance requirements or changing unrelated work.
- **BREAKING**: revoke persistence of machine-specific TUI settings into the shared repository profile. Preserve live consumption of portable settings, explicit overrides, local user data and recoverable global installation.
- Consolidate useful operational facts and active development evidence into maintained documents; remove redundant research, completed incident reports, obsolete inventory and tracked caches. Keep current specifications and unfinished tasks intact.
- Add focused regression checks for public report output and the shared/local configuration boundary, plus a repeatable repository hygiene check using synthetic data.
- Update repository presentation and instructions for the public pack. Existing command/package identifiers remain compatible; remote renaming, Git history rewriting and publication are separate actions.

## Capabilities

### New Capabilities

- `public-source-hygiene`: portable tracked sources, public output, bounded documentation retention and repeatable hygiene checks.

### Modified Capabilities

- `linked-global-kit`: shared configuration remains portable and native runtime settings stay local.
- `git-project-memory`: retain only useful project-owned knowledge that is appropriate for the repository's publication boundary.
- `bounded-tool-resources`: express existing real-consumer acceptance without embedding that consumer's identity or location.

## Impact

Global principles, repository instructions, project-memory skill resources, README and maintained docs, OpenSpec references, configuration/launcher installation boundaries, public delegation reports and relevant fixtures/checks. The current Windows/Codex delivery remains supported; this does not claim additional agents or platforms. The existing Rust migration and other active changes keep their accepted requirements and unfinished state. Global instructions and changed runtime behavior must be verified outside this checkout; private inputs and recovery copies remain machine-local.

## Context

See [proposal](proposal.md). The installed launcher selects a linked file profile; the existing acceptance record proves that native TUI trust/model writers can modify that source. Public report projection also contains consumer-specific exceptions. Documentation mixes operating guidance, migration evidence and completed investigation narratives. Four other changes and pre-existing source edits remain unfinished.

## Goals / Non-Goals

**Goals:** establish the publication boundary in current source and installed behavior, keep live reusable configuration, preserve useful evidence and reduce documentation maintenance cost.

**Non-Goals:** rewrite Git history, publish or rename the remote repository, rename compatible binaries/crates, add platform support, complete unrelated active changes, or introduce routine model-backed publication gates.

## Decisions

1. **Own the rule once.** Add the general boundary and retention rule to portable principles. Repository guidance identifies the pack and its maintained document routes. The memory skill applies the boundary when choosing what to retain; it does not maintain a second policy manual.
2. **Separate portable settings from native writes.** Ordinary launch reads portable source through a Rust bridge and passes native `-c` leaf arguments, without selecting a shared file profile. Native writers use the existing machine-local base `config.toml`. This also matches unprofiled management consumers and lets the normal link journal retire the legacy shared-profile link. Shared policy stays live; model, reasoning, UI and notice defaults apply when corresponding local preferences are absent. Trust records never enter shared arguments. Explicit user profiles and invocation overrides keep their existing bypass/precedence. Before retiring a legacy source link, merge its machine settings into the base, preserving local values on conflict and both originals in private recovery files. This local preparation persists through connection rollback/disconnection. The PowerShell entry point uses a verified immutable Rust manager built during explicit setup; runtime never compiles. Native launcher uses the same module directly.
3. **Generalize public output and fixtures.** Remove real-consumer exceptions from public formatting; tests use arbitrary synthetic project names and check actual command output. Graph queries use owned generic fixture context or explicit local inputs, never a private project's name.
4. **Keep useful knowledge, remove narrative duplication.** Maintain a short documentation map, installation/operation guides, development/check commands, decisions, current specs and necessary active evidence. Merge current restrictions and repeatable checks before deleting old inventory, research and closed reports. Retarget references to living owners and remove the 18 closed OpenSpec archive snapshots after their current requirements and useful restrictions are preserved. Keep all four unrelated active changes and their task states. Archival location grants no privacy exception; Git history remains outside this cleanup.
5. **Check the boundary without storing private terms.** A small Rust check scans Git-listed source and optionally caller-supplied local terms, emits locations/categories without matched text, validates local Markdown targets and rejects tracked runtime caches. Synthetic tests cover meaningful failures. The checker is a supporting guard, not a proof that every confidential fact is recognizable.

## Risks / Trade-offs

- Native config persistence and precedence → verify installed-version behavior through isolated actual CLI/TUI entry points and preserve explicit overrides; do not stop the session's shared proxy.
- Removing active evidence or user changes → retain a private pre-change snapshot, preserve unfinished task states, inspect incoming references and move necessary facts before deletion.
- Breaking linked global instructions → verify source identity and fresh external consumer loading after edits.
- Old commits retain removed data → disclose this boundary; publication history remains a separate user-owned action.
- Transitional Python/PowerShell consumers still exist → keep small compatibility edits and applicable tests until the separate Rust migration replaces them; all new executable mechanisms are Rust.

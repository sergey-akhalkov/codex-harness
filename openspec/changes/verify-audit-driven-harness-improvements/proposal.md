## Why

The supplied audit identifies concrete correctness failures and avoidable work in the existing harness, but several proposed guarantees need tighter boundaries and some current specifications encode the unsafe behavior. This change closes every enumerated audit finding with traceable acceptance evidence and evaluates the remaining optimization candidates without representing hypotheses, smaller byte counts or consistent reports as proven task or subscription savings.

## What Changes

- Make RTK observation publication, retention and recall safe across processes; validate retained metadata and select compression using the complete delivered presentation.
- Preserve native model/effort precedence and expose the source of the effective choice without copying the native configuration loader.
- Repair baseline naming, validation, concurrent publication, location, comparability and bounded output; distinguish recently active sessions from usage inside a time interval and preserve measurement coverage.
- Separate installed-runtime integrity from source-freshness diagnostics; reject unsuitable build candidates early and evaluate shorter development/build cycles without weakening publication integrity.
- Replace prefix-and-age TEMP deletion with verified ownership and live leases. **BREAKING:** unproven legacy scratch is no longer automatically deleted.
- Authenticate the owned xAI endpoint and bind sessions to compatible generations. **BREAKING:** unidentified listeners are no longer accepted as trusted transports.
- Connect existing outcome evidence, independent acceptance and benefit decisions; use real experimental units and account for incomplete, failed and delegated work.
- Verify the skill and references actually consumed; evaluate instruction layout, deferred tool discovery, stable prompt sections and deterministic aggregation through existing owners.
- Diagnose and close the observed semantic-tool readiness gap without assuming that activation, process existence or an automatic retry establishes working navigation.
- Add reproducible Windows/MSVC CI using existing checks, with separate installed-consumer coverage and explicitly selected model-backed evaluation.
- Keep a complete finding-to-requirement-to-task map in `design.md`. Required correctness work cannot close on a rejected optimization; optional candidates require an evidenced decision and cannot silently become defaults.

### Modified Capabilities

- `token-audit`: valid immutable baselines, bounded comparisons, explicit temporal accounting and trustworthy incremental analysis.

- `global-code-tools`: truthful semantic readiness and cause-directed recovery.

## Impact

Affected implementation owners are `crates/harness-rtk`, `crates/token-audit`, native launcher/build/transport/evaluation/Serena modules in `crates/harness-core`, their existing Rust integration tests, the installation lifecycle and a future `.github/workflows` configuration. Existing documentation and skill owners receive only necessary operational corrections during implementation; externally maintained OpenSpec workflows remain untouched.

Planning creates no runtime changes, installations, model-backed trials, commits or remote writes. Implementation must preserve current command compatibility, Rust ownership, live shared configuration, native Codex fallback, unrelated state and global delivery. No new runtime, database, model provider, billing route or mandatory background agent is proposed. Performance adoption is conditional on scoped evidence; no finite audit or test suite provides a universal 100% improvement guarantee.

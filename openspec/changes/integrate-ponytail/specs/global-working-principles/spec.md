# Spec Delta

## ADDED Requirements

### Requirement: Ponytail and harness have distinct instruction ownership

Equivalent rules and workflows SHALL have one owner. The original installed Ponytail package SHALL supply upstream-owned rules; harness guidance SHALL retain additional obligations without copying upstream bodies. Deduplication SHALL preserve controlling instructions, agreed acceptance, authority, evidence, project guidance and protected external workflows.

#### Scenario: A local instruction is fully covered
- **WHEN** comparison and actual loading establish equivalent Ponytail coverage
- **THEN** the equivalent local instruction is removed and its upstream source is identified in the existing ownership guide

#### Scenario: Coverage is partial
- **WHEN** the harness requires additional obligations beyond the upstream rule
- **THEN** those obligations remain concise supplements without silently weakening them

#### Scenario: A specialized or protected workflow differs
- **WHEN** a similarly named upstream skill has a different purpose or controlling requirements
- **THEN** the distinct workflow remains and protected OpenSpec resources are not edited

### Requirement: Consolidation follows verified availability

Ponytail SHALL be installed and its guidance observed before dependent instruction removal. Existing source and instruction-size checks SHALL remain in force. Efficiency gains SHALL NOT be claimed without measurements.

#### Scenario: Only package discovery passed
- **WHEN** a package is listed but loading has not been observed
- **THEN** discovery alone does not justify removing local instruction coverage

## Why

Полезные способы работы теряются между задачами, а ручное создание и обслуживание скиллов во всех репозиториях не соответствует желаемой автономности. Нужен глобально поставляемый цикл обучения на проверенном опыте, который принимает полезные изменения и обеспечивает применение нового скилла уже в текущей сессии, включая продолжение после сжатия контекста.

## What Changes

- Поставить один глобальный `skill-evolution`, использующий доступный `skill-creator`: создание, уточнение, объединение и вывод скиллов из использования по наблюдаемым результатам работы. Отделять процедурные навыки от фактов, предварительных идей и команд, у которых уже есть место в памяти или инструментах проекта.
- Автономно вести проектные скиллы в Git текущего репозитория, сохраняя чужие изменения. Общие навыки поставлять из одного канонического источника harness после проверки переносимости; черновики держать вне каталогов обнаружения.
- Принимать изменения через соразмерные сравнения с отсутствием скилла или предыдущей версией, проверяя результат, выбор подходящего скилла, совместимость, время и стоимость всего цикла. Защитить критерии приёмки от изменения самим кандидатом.
- Обеспечить обратимую активацию проверенной ревизии, обнаружение конфликтов, ограниченные повторные попытки и сохранение действующей версии при неуспехе. Обычное обслуживание в разрешённой области не требует ручного ревью каждого скилла.
- Добавить компактный производный каталог и доставку изменений в текущую сессию; восстановление после compaction/resume и передача актуального навыка субагентам входят в обязательную приёмку. Перезапуск сессии не считается заменой этого результата.
- Подключить механизм через существующий lifecycle kit и проверить реальную работу в двух репозиториях вне harness, свежем clone и текущей сессии. Пилот является этапом приёмки всей системы; регистрация файлов или подготовка отчёта не означают завершения реализации.

## Capabilities

### New Capabilities

- `autonomous-skill-evolution`: отбор опыта, владение знаниями, автономное изменение и публикация скиллов, перенос общих навыков, восстановление и обслуживание библиотеки.
- `skill-evaluation`: проверяемые условия принятия кандидатов, независимые испытания, защита критериев, измерение полезности и ограничение расходов.
- `skill-session-awareness`: актуальный каталог, активация в работающей сессии, восстановление контекста и применение субагентами.

### Modified Capabilities

- `linked-global-kit`: расширить контракт обновлений для активируемых системой скиллов в работающих сессиях и добавить автономное согласование только принадлежащих kit регистраций без копирования исходников.

## Impact

Предполагаемые точки реализации: `.agents/skills/skill-evolution/`, переносимая политика в `global/`, инструменты в `tools/`, существующие `global/kit.psd1`, `global/hooks.json`, `tools/kit.psm1` и установщик. Существующую диагностику и её границы сохраняем. Проверки расширяют подходящие consumers из `tests/`, включая native CLI, App Server и Windows TUI; App Server не подменяет проверку основного CLI.

Интеграция использует выбранную [проектную Git-память](../adopt-project-memory-and-native-workflows/specs/git-project-memory/spec.md) без второго авторитетного хранилища. Эта зависимость ещё находится в реализации; самостоятельная установка системы навыков должна уметь использовать уже существующие записи проекта. Первая целевая среда — Windows, PowerShell 7.4+ и установленный Codex CLI 0.153.4; актуальные runtime-контракты требуют проверок, перечисленных в дизайне.

Фоновый обход неактивных репозиториев, собственный оркестратор, автоматический commit/push, перезапись сторонних или встроенных скиллов и самостоятельное изменение правил контроля в объём не входят. Этот change содержит план; создание артефактов не активирует механизм и не запускает модельные испытания.

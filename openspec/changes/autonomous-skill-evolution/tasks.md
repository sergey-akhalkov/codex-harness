## 0. Проверить измеримость на одном существующем скилле

Это первый рабочий путь до общей автоматизации. Пилот не активирует изменения в пользовательской библиотеке и не заменяет обязательную глобальную приёмку. Все новые поддерживаемые executable helpers и проверки пишутся на Rust; shell — PowerShell.

- [ ] 0.1 Выбрать existing owned скилл с реальной проверяемой задачей и определить baseline `L`, shortening/retirement candidate `L'`, неизменные требования/model/effort/tools, локальные test targets и ограниченный бюджет. Переиспользовать существующий runner; до модельного запуска проверить недоступность для записи oracle/baseline/control files и отсутствие влияния на управляющую сессию. Завершение: через фактический entry point выполнена первая пара, известны effective catalogue/revisions, observable usage и результат native acceptance, а неподдержанные измерения отмечены явно.
- [ ] 0.2 Дополнить пилот подходящим, похожим неподходящим и boundary/failure сценариями с не использованным при refinement вариантом. Проверить естественный выбор в библиотеке, metadata/body/use, обе стоимости вместе с неудачами, порядком/cache conditions, временем и доступной quota attribution. Завершение: для кандидата получен accept/reject/inconclusive по заранее объявленному плану; нет вывода о бесполезности из одного успешного baseline, solution leakage или выдуманного процента подписки.
- [ ] 0.3 По измерениям выбрать и зафиксировать в существующей owning записи воспроизводимые параметры дальнейшей приёмки: observable units, scope/period и пределы бюджетов, catalogue baseline, task mix/horizon, существенный эффект, estimator/uncertainty method и план независимых acceptance batches. Завершение: на примерах данных однозначно вычисляются три решения, разные cost/capability claims различаются, новая acceptance выборка не используется для настройки порогов; pilot reject/inconclusive не закрывает последующие benefit задачи и не вызывает бесконечных повторов.

## 1. Проверить конкретные runtime-контракты

Пункт 1.1 сохраняет историческое evidence разрешённого тогда hook-пути; текущую hooks-off поставку и ограничения закрывают только последующие фактические проверки.

- [x] 1.1 В owned probe проверить установленный Codex CLI и его схемы: обнаружение созданного/обновлённого скилла, additionalContext для выбранных событий, SessionStart startup/resume/compact, включая automatic mid-turn continuation. Переиспользовать consumers/ConPTY из `tests/`; сохранить версии, фактические события и ограничения. Завершение: определён и продемонстрирован поддержанный путь доставки в текущую CLI-сессию; отдельный App Server или restart-only результат не закрывает задачу.
- [ ] 1.2 Проверить предложенную публикацию на Windows: целый новый пакет, атомарное переключение descriptor и неизменяемые пути ресурсов существующего пакета, сбой между шагами и rollback. Завершение: failure-injection probe показывает только целостные используемые ревизии через live source link и сохраняет чужие изменения; результат определяет конкретный примитив публикации.
- [ ] 1.3 Выбрать и проверить существующий способ исполнения eval в изолированном owned target с недоступными для записи baseline/oracles/control files. Завершение: кандидат, пытающийся изменить oracle или выйти за test target, не может получить успешный verdict; зафиксированы runtime dependencies и пределы изоляции без изменений прав основной сессии.

## 2. Отбор опыта и авторство

- [ ] 2.1 Используя применимый `skill-creator`, создать глобальный `skill-evolution` с режимами create/update/consolidate/retire и общей политикой владения. Поставить короткий глобальный маршрут к workflow, не переопределяя встроенный creator. Завершение: проверки примеров различают полезную процедуру, факт, гипотезу, существующий инструмент и routine/read-only no-op; creator пишет только в переданный staging.
- [ ] 2.2 Реализовать хранение candidate/evidence вне discovery с переиспользованием существующей Git-памяти проекта; идентифицировать worktree, package/parent hashes и значимые зависимости. Завершение: дубликаты не размножаются, секреты и сырые transcripts не попадают в пакет/отчёт, отсутствует auto stage/commit/push, стабильный незакоммиченный пакет поддерживается.
- [ ] 2.3 Реализовать определение владельца, существующих совпадений и защищённых областей: control policy, evaluator, сам evolution/creator, third-party/system skills и explicit disablement. Завершение: проверки collision, symlink escape, попытки самоизменения и внешней инструкции сохраняют запрещённые targets; обычный owned предметный skill остаётся доступен для разрешённого развития.
- [ ] 2.4 Добавить signal-driven review по ошибкам/use/ложному выбору, наблюдаемым затратам, overlap/replacement, изменению модели/зависимости и catalogue pressure; учитывать eligible opportunities отдельно от частоты вызовов. Завершение: рассматриваются shortening/merge/retire и addition, без нового сигнала нет отдельного model run, одинаковая неудача и rename без новых данных не перезапускают цикл, низкая частота не вызывает отключение, timeout/quota/unavailable сохраняют прежнюю версию.
- [ ] 2.5 Реализовать бюджеты эпизода и общего периода владельца, reservation до dispatch, учёт обеих сторон и всех неудачных ревизий, reconciliation после restart и потерянного ledger. Завершение: множество малых эпизодов не превышает суммарный enforceable limit, rename/restart не обнуляют расход, unknown quota не становится нулём/бесконечностью; после исчерпания или неопределённого резерва обучение ждёт, ordinary task execution продолжается.

## 3. Оценка полезности

- [ ] 3.1 Реализовать сравнения add/absence, update-or-shortening/old-version, merge/old-set и retire/retention с фиксированной surrounding library, model/effort/tools и свежими контекстами. Завершение: исполняются intended, negative, protected overlap и boundary/failure cases с отдельным held-out вариантом; effective discovery и порядок/cache conditions зафиксированы, отсутствие use в removal/negative не считается bypass, авторская переписка не передаётся evaluator.
- [ ] 3.2 Подключить детерминированные project/artifact checks, проверку фактического чтения/применения скилла и защищённую фиксированную rubric для необходимой субъективной оценки. Завершение: skill bypass, запись в oracle/result/baseline и ложный self-report не проходят; revision/dependency drift инвалидирует затронутое evidence.
- [ ] 3.3 Реализовать вычисляемый accept/reject/inconclusive по таблице design: актуальность evidence, must-pass/selection, protected regressions, policy-bound claim и budgets. Учесть полную стоимость, net-savings horizon и capability improvement без заявления об экономии. Завершение: shortcut с пропущенной проверкой отклонён, недостаточные/неатрибутируемые данные inconclusive, один удачный run и отсутствие значимой разницы не дают ложной приёмки; повторные looks/candidates следуют выбранному плану, модели сторон совпадают с действующей политикой.
- [ ] 3.4 Описать и проверить переходы небольшого Rust-ядра решений/резервов/допуска: начальное состояние, разрешённые переходы и инварианты из design. Завершение: native checks исполняют success/failure/unknown, stale revision, interrupted reservation, rename/restart, period exhaustion и catalogue overflow, включая ограниченный перебор малых состояний; в evidence указана граница этого перебора, проверки не выдаются за доказательство полезности скилла или реализации всех внешних зависимостей.

## 4. Обратимая публикация и обслуживание

- [ ] 4.1 Реализовать публикацию проверенного package hash из staging в owning project source по результату 1.2: compare-and-swap baseline, короткая блокировка, целостная ревизия, безопасные canonical paths. Завершение: concurrent writers, изменение ресурса после eval и прерывание multi-file update не дают принять смешанную или непроверенную версию.
- [ ] 4.2 Реализовать journal/recovery/rollback с проверкой текущего владения перед восстановлением и раздельным статусом accepted, published и delivered. Завершение: незавершённая операция восстанавливается после перезапуска helper, foreign edit не затирается, ссылка не используется для рекурсивного удаления её цели, неполное восстановление имеет точную причину.
- [ ] 4.3 Реализовать promotion в canonical harness после проверки origin и второго независимого проекта, очистки локальных assumptions/secrets и проверки dependencies. Завершение: переносимый кандидат публикуется через отдельную глобальную операцию, непереносимый остаётся local/pending, пересекающиеся локальные и глобальные идентичности согласуются без потери проектного поведения или незакоммиченной работы.
- [ ] 4.4 Реализовать evaluated consolidation и сначала обратимый retirement, согласование supported references и хранение нужной recovery/resource истории вне discovery. Завершение: replacement сохраняет прежние suites, удаление скилла сравнивается с его сохранением, inconclusive/низкая частота/давление каталога не отключают required поведение, неизвестные consumers предотвращают destructive removal; откат возвращает пригодный пакет и не затирает чужие правки. Physical cleanup имеет отдельную проверку владельца/readers и не требуется ради экономии discovery.

## 5. Актуальные навыки в сессии

- [ ] 5.1 Реализовать scoped catalogue с canonical identity, applicability, path/revision, disablement, дедупликацией и конфликтами sources; добавить измерение полного owned metadata до truncation и admission guard по откалиброванному бюджету. Завершение: candidates/retired/чужие project skills исключены, каталог восстановим без обнуления budget ledger; рост сверх бюджета pending, overflow baseline допускает только evaluated reduction, protected контекст сохранён, неполный delivered list имеет работающий ограниченный маршрут к остатку.
- [ ] 5.2 Подключить разрешённое чтение принятого descriptor, revision/retirement delta в текущем turn и изменение от другого writer перед следующим use. Завершение: matching task без `$skill` использует новую ревизию, update/rollback/retirement наблюдаемы в следующем действии; retired workflow не выбирается из старого контекста, регистрация без такого наблюдения не считается complete, уже загруженные tokens не объявляются удалёнными/возвращёнными.
- [ ] 5.3 Доказать и реализовать поддержанный hooks-off путь восстановления compact/resume и передачу релевантного path/revision детям; подтверждённый в 1.1 SessionStart-путь остаётся историческим evidence и не разрешает включение ordinary hooks. Завершение: manual и automatic mid-turn compaction восстанавливают актуальность до продолжения, resume учитывает disablement, ребёнок без fork и уже работающий ребёнок применяют нужную ревизию с честной атрибуцией прежних результатов; отсутствие допустимого рабочего механизма оставляет задачу открытой.
- [ ] 5.4 Ограничить выбранный допустимый путь доставки по времени/объёму, экранировать недоверенные поля каталога и сохранить принятый режим явных проверок. Завершение: malformed metadata, injection text, timeout и неизвестная runtime capability дают ограниченный incomplete результат; ordinary diagnostic/context/Stop hooks остаются выключенными, RTK-исключение сохранено, нет рекурсивного обучения, Stop loops, потери явных проверок или model calls на каждом событии.

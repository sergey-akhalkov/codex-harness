## ADDED Requirements

### Requirement: Executable autonomous outcome assignments

Assignments SHALL name their consumer, checkout, committed base, exact input and owned output paths, material invariants, acceptance checks and escalation boundaries. The executor SHALL independently investigate, implement, run applicable checks and correct local errors within that scope. Source bodies SHALL be supplied only as an explicit fallback when reading is unavailable. Corrections SHALL preserve the original capable executor's work. Stable constraints, task context and optional references SHALL have distinct owners without repeating whole manuals.

#### Scenario: Executor repairs existing Rust behavior
- **WHEN** an installed executor receives an owned Rust defect with bounded acceptance
- **THEN** it independently reads the existing source, identifies a symbol and caller, applies the correction, runs the applicable native check and returns evidence that the lead consumes without supplying file bodies or repairing its code

#### Scenario: Ordinary implementation error
- **WHEN** the executor encounters a syntax error or incorrect API name and its tools work
- **THEN** it investigates and corrects the error within its assignment; it escalates changes to the agreed outcome, material architecture, missing authority or a concrete unavailable dependency

### Requirement: Verified executor shell capability

Dispatch and continuation SHALL preserve the owner's installed PowerShell 7 capability and SHALL NOT silently fall back to Windows PowerShell 5.1 or install another shell. The sandbox-specific restriction on packaged PowerShell SHALL remain scoped to sandboxed execution. Capability evidence SHALL identify the actual runtime version and process, not merely a requested shell argument. An unavailable dependency SHALL name the failing owner, evidence and supported boundary without claiming model failure.

#### Scenario: Unsandboxed owner uses packaged PowerShell 7
- **WHEN** the effective executor configuration disables sandboxing and the owner's existing PowerShell 7 is a packaged installation
- **THEN** dispatch retains that usable capability and the executor's native tool executes PowerShell 7

#### Scenario: No permitted PowerShell is available
- **WHEN** the effective execution policy leaves no permitted PowerShell 7
- **THEN** dispatch reports the prerequisite failure before model work and preserves partial work; it neither starts Windows PowerShell 5.1 nor changes sandbox permissions

### Requirement: Evidence-based delegation cost comparison

Acceptance SHALL compare a minimal comparable set of baseline and candidate tasks using existing measurement sources, separating elapsed time to acceptance, lead tokens and interventions, executor totals, rework and quality. Missing reliable quantitative evidence SHALL remain explicit. Agent counts, output bytes and launch counts SHALL NOT imply subscription savings. Explicit configured profiles and their effective model, provider, billing and supported effort SHALL remain observable and unchanged unless explicitly selected otherwise.

#### Scenario: Cost telemetry is incomplete
- **WHEN** accepted behavior is verified but comparable lead or executor accounting is unavailable
- **THEN** the result reports verified properties and missing metrics without inventing savings or weakening acceptance
